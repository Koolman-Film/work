# หักสิทธิวันลาแทนการหักเงิน (บทลงโทษขาดงาน/มาสาย) — Design

**Date:** 2026-07-19
**Status:** Approved (design), pending implementation
**Author:** brainstormed with Claude

## Summary

ลูกค้าเขียนว่า *"หักเงิน**หรือสิทธิ** 1 วัน"* แต่ระบบหักเป็นเงินอย่างเดียว
งานนี้เพิ่มทางเลือกให้แอดมิน**ตัดสินเป็นครั้ง ๆ** ว่าโทษครั้งนั้นจะจ่ายด้วย
เงินหรือด้วยสิทธิวันลา

**นี่คือการแตะทั้งสูตรเงินเดือนและยอดสิทธิลา** — สองระบบที่พนักงานตรวจสอบ
ยอดเองได้ทั้งคู่ จึงต้องย้อนกลับได้และห้ามหักซ้ำเด็ดขาด

มี schema migration (ตารางใหม่ 1 ตาราง + enum ใหม่ 1 ตัว) — ไม่แก้ตารางเดิม

## Context

### ลูกค้าขออะไร (ยกจากเอกสาร Canva ตรงตัว)

> *"มาสายครบ 3 ครั้ง = **หักเงินหรือสิทธิ 1 วัน** ณ เดือนที่ครบ"*
> *"ลงเวลาตั้งแต่ 9.31 น. เป็นต้นไป ... **ไม่กดลา = หักเงินหรือสิทธิ 1 วัน**"*
> *"กดลางาน เป็นชั่วโมง, ครึ่งวัน = หักเงินหรือสิทธิตามการลาเป็นชั่วโมง, ครึ่งวัน"*
> *"\*ทุกเงื่อนไขสามารถแก้ไขได้โดย admin หรือการคีย์มือให้ไม่หัก **แล้วแต่พิจารณา**\*"*

คำว่า "หักเงินหรือสิทธิ" ปรากฏ 3 ครั้ง และ "แล้วแต่พิจารณา" คือเหตุผลที่งานนี้
ให้แอดมินตัดสินเป็นครั้ง ๆ ไม่ใช่ตั้งเป็นนโยบายตายตัว

### ขอบเขตที่แคบลงหลังอ่านโค้ด

ข้อที่ 3 (**ลาเป็นชั่วโมง/ครึ่งวัน**) **ระบบทำถูกอยู่แล้ว** — ลาในสิทธิตัดจาก
โควตา ลาเกินสิทธิหักเงิน (`src/lib/leave/over-quota.ts`) ไม่ต้องทำอะไรเพิ่ม

เหลือบทลงโทษ **3 ชนิด** ที่ทุกวันนี้เป็นเงินล้วน และทั้งสามใช้ `dayAmount`
ตัวเดียวกันที่ `calc.ts:392`:

| ชนิด | เกิดเมื่อ | รู้ผลเมื่อ |
|---|---|---|
| `Absent` | ไม่มาทำงานและไม่กดลา | ทันที (คีย์มือ / สิ้นวัน) |
| `LateThreeStrike` | สายครบ N ครั้งในรอบ | **ตอนคำนวณเงินเดือนเท่านั้น** |
| `SevereLate` | สายเกิน 30 นาที และไม่มีใบลา | ตอนคำนวณเงินเดือน |

`LateThreeStrike` ไม่มีตัวตนจนกว่าจะนับสายทั้งรอบ — จึงเลือกตอนคีย์มือไม่ได้
นี่คือเหตุผลที่ต้องมีจุดตัดสินที่หน้ากระทบยอดด้วย

### สภาพจริงบน production

```
ลากิจ      สิทธิ 3 วัน/ปี   27 คนใช้   55.3 วัน  → เกือบเต็มโควตา
ลาพักร้อน   สิทธิ 6 วัน/ปี    6 คนใช้   23.6 วัน  → 40 คนยังไม่แตะ
ลาป่วย     สิทธิ 30 วัน/ปี  10 คนใช้   13.3 วัน  → เหลือเยอะ
ลาคลอด    สิทธิ 120 วัน/ปี   1 คนใช้   43 วัน
```

**ลาพักร้อนตั้ง `overQuotaPolicy = Block`** — ถ้าหักสิทธิจนติดลบ พนักงานคนนั้น
จะลาพักร้อนไม่ได้ไปตลอดทั้งปี ผลข้างเคียงแรงกว่าบทลงโทษที่ตั้งใจ จึง**ห้าม
หักเกินยอดคงเหลือ**

## Decision

### การตัดสินใจ 4 ข้อที่ตกลงกับผู้ใช้

1. **ใครตัดสิน:** แอดมินเลือกเป็นครั้ง ๆ (ไม่ใช่ตั้งค่าระดับบริษัท/รายคน)
2. **ประเภทลา:** แอดมินเลือกเองตอนกด พร้อมเห็นยอดคงเหลือของแต่ละประเภท
3. **จุดที่เลือก:** ทั้งหน้าคีย์มือ **และ** หน้ากระทบยอด — เก็บที่เดียว แก้ได้สองที่
4. **สิทธิไม่พอ:** ปิดตัวเลือกนั้น (ไม่หักจนติดลบ ไม่หักครึ่ง ๆ)

### สถาปัตยกรรม: เก็บ "การตัดสินใจ" ไม่ใช่ "ยอดคงเหลือ"

**ทางที่ไม่เลือก:** เขียนลด `LeaveEntitlement.adjustmentMinutes` ตอน publish
— การคำนวณเงินเดือนซ้ำได้หลายรอบโดยออกแบบ ถ้าการคำนวณไปเขียนสิทธิ
**กดคำนวณ 10 ครั้ง = สิทธิหาย 10 วัน** ความถูกต้องจะขึ้นกับว่าเราเขียน guard
ครบทุกทางออกไหม ซึ่งเป็นเงื่อนไขที่พลาดง่ายและพังเงียบ

**ทางที่เลือก:** เก็บการตัดสินใจเป็นแถวของตัวเอง แล้วให้ยอดคงเหลือ**ลบออก
ตอนอ่าน** — ตรงกับที่โค้ดเบสนี้ทำอยู่แล้ว (`usedMinutes` ไล่รวมใบลาสด ๆ ไม่เก็บ
ยอดสะสม)

- **ไม่มีการเขียนข้อมูลตอนคำนวณเงินเดือน** → หักซ้ำไม่ได้โดยโครงสร้าง
- ลบแถว → สิทธิกลับมา เงินกลับมาหัก ย้อนกลับสมบูรณ์
- **ไม่มีแถว = พฤติกรรมเดิมเป๊ะ ๆ** ของเดิมไม่ถูกแตะ

## Architecture

### ตารางใหม่

```prisma
enum PenaltyKind {
  Absent
  LateThreeStrike
  SevereLate
}

/// แอดมินตัดสินว่าบทลงโทษของเดือนนั้นจ่ายด้วยสิทธิวันลาแทนเงินเท่าไร
/// ไม่มีแถว = จ่ายด้วยเงินทั้งหมด (พฤติกรรมเดิม)
///
/// ห้ามให้การคำนวณเงินเดือนเขียนตารางนี้ — ตารางนี้คือ "คำสั่งของคน"
/// การคำนวณอ่านอย่างเดียว จึงกดคำนวณซ้ำได้โดยไม่หักซ้ำ
model AttendancePenaltySettlement {
  id          String      @id @default(uuid()) @db.Uuid
  employeeId  String      @db.Uuid
  employee    Employee    @relation(fields: [employeeId], references: [id], onDelete: Cascade)
  /// รอบเงินเดือน "YYYY-MM" — ป้ายเดียวกับ Payroll.month
  month       String
  kind        PenaltyKind
  leaveTypeId String      @db.Uuid
  leaveType   LeaveType   @relation(fields: [leaveTypeId], references: [id], onDelete: Restrict)
  /// กันเงินไว้กี่วัน (ตัวหักลบในสูตรเงิน) — ตรึงตอนกด
  days        Decimal     @db.Decimal(5, 2)
  /// ตัดสิทธิกี่นาที — ตรึงตอนกด
  minutes     Int
  /// ปีที่ตัดสิทธิ = ปีตามป้ายเดือน ไม่ derive ใหม่ที่อื่น
  periodYear  Int
  note        String?
  createdById String?     @db.Uuid
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt
  deletedAt   DateTime?

  @@unique([employeeId, month, kind])
  @@index([employeeId, periodYear, leaveTypeId])
  @@index([month])
  @@index([deletedAt])
}
```

`days` และ `minutes` **ตรึงค่าตอนกด ไม่คำนวณใหม่** — แบบเดียวกับ
`LeaveRequest.chargedMinutes` ที่ตรึงตอนอนุมัติ ถ้าแอดมินแก้ "ชั่วโมงทำงาน
มาตรฐาน" (`LeaveConfig`) ทีหลัง โทษที่ตัดสินไปแล้วต้องไม่ขยับ

**ความสัมพันธ์ของสองค่านี้:** ตอนเขียนแถว `minutes = days × standardDayMinutes`
(จาก `LeaveConfig` ณ ขณะนั้น) หลังจากนั้นทั้งคู่เป็นค่าตายตัวและ**ไม่มีใคร
คำนวณจากอีกตัวอีกเลย** — ฝั่งเงินอ่าน `days` ฝั่งสิทธิอ่าน `minutes`

**`days` บันทึกเป็นจำนวนเต็มวันเสมอ** สำหรับบทลงโทษทั้ง 3 ชนิด (ทุกชนิดเป็น
หน่วย "1 วัน") ที่ประกาศเป็น `Decimal(5,2)` เพราะมันถูกนำไปคูณกับ `Decimal`
ในสูตรเงิน — ให้ชนิดข้อมูลตรงกับที่โมดูลเงินเดือนใช้ ไม่ใช่เพื่อรองรับเศษวัน

### ไฟล์ที่แตะ

**`src/lib/payroll/penalty-settlement.ts`** *(ใหม่ — pure)*

```ts
export type SettlementDays = { Absent: number; LateThreeStrike: number; SevereLate: number };

/** วันที่ยังต้องจ่ายด้วยเงิน หลังหักส่วนที่จ่ายด้วยสิทธิแล้ว
 *  clamp ที่ 0 เสมอ — ดูเหตุผลใน Reversibility */
export function moneyDaysFor(actualDays: number, settledDays: number): number;
```

**`src/lib/payroll/calc.ts`** — เปลี่ยน 3 บรรทัดให้ผ่าน `moneyDaysFor`:

```ts
const settled = input.penaltySettlement ?? { Absent: 0, LateThreeStrike: 0, SevereLate: 0 };
const absentDays = moneyDaysFor(absentCount, settled.Absent);
const strikeDays = moneyDaysFor(latePenalty.threeStrikeDays, settled.LateThreeStrike);
const severeDays = moneyDaysFor(latePenalty.severeDays, settled.SevereLate);
```

**`src/lib/payroll/run.ts`** — โหลด settlement ของเดือนนั้นทั้งชุด (query เดียว
ทั้ง batch, `deletedAt: null`) แล้วส่งเข้า `input.penaltySettlement` ของแต่ละคน
เหมือนที่ส่ง config/attendances อยู่แล้ว **`calc.ts` ยังเป็น pure ไม่ query เอง**

`penaltySettlement` เป็น optional ใน `CalcInput` โดยตั้งใจ — ต่างจาก
`remainingMinutes` ตรงที่ "ไม่มี settlement" เป็นสถานะปกติของพนักงานเกือบทุกคน
ไม่ใช่การลืมส่ง และค่า default (ศูนย์ทั้งสามชนิด) คือพฤติกรรมเดิมที่ถูกต้อง

โหมด flat `lateDeduction` (ตอนปิดกฎ N ครั้ง) **ไม่เกี่ยว** — เป็นค่าปรับต่อครั้ง
ไม่ใช่หน่วย "1 วัน" ตรงกับที่ตัดสินไว้ในสเปกวันเดียวกัน

**`src/lib/leave/balance.ts`** — `remainingMinutes()` รับพารามิเตอร์ที่ 3
`penaltyMinutes: number` แบบ **บังคับ (required)**

เรียกจาก 5 จุด: `balance.ts` (3), `leave/admin.ts:282`,
`leave/approval-preview.ts:46` — พารามิเตอร์บังคับทำให้จุดที่ยังไม่แก้
**compile ไม่ผ่าน** ถ้าเป็น optional แล้วลืมสักจุด ยอดคงเหลือตรงนั้นจะสูงเกินจริง
เงียบ ๆ และพนักงานจะลาเกินสิทธิได้ (บทเรียนตรงจาก
`ConfigForPayroll.workingDaysPerMonth` ที่เป็น optional แล้ว default 30 เงียบ ๆ)

**`src/lib/leave/penalty-minutes.ts`** *(ใหม่)* — คู่ขนานกับ `usedMinutes`:
ตัวเดี่ยว `penaltyMinutes(employeeId, leaveTypeId, year)` และตัว bulk
`penaltyMinutesBy(employeeIds, year)` (groupBy) ให้ตรงกับรูปแบบ query ของแต่ละ
จุดเรียก — จุดที่เป็น loop ใช้ตัวเดี่ยว จุดที่เป็น bulk report ใช้ groupBy

**`src/lib/payslip/document.ts`** — breakdown ต้องเขียนว่า
*"ขาดงาน 1 วัน — หักจากสิทธิลาพักร้อน"* ถ้าเงินเป็น 0 เพราะจ่ายด้วยสิทธิ
**ห้ามให้หายไปเฉย ๆ** ไม่งั้นพนักงานเห็นว่าไม่โดนหัก แล้วไปเจอสิทธิลาหายทีหลัง

**หน้าจอ**
- `src/app/(admin)/admin/attendance/manual/` — ตอนบันทึกขาดงาน: เลือก
  หักเงิน (ค่าเริ่มต้น) / หักสิทธิ + dropdown ประเภทที่แสดงยอดคงเหลือ
  ประเภทที่ไม่พอ **disabled**
- `src/app/(admin)/admin/payroll/reconcile/` — รวมบทลงโทษทั้ง 3 ชนิดของเดือน
  แก้การตัดสินใจได้ **อ่านอย่างเดียวเมื่อแถวนั้น Published/Locked**

## กรณีขอบ

| กรณี | กติกา |
|---|---|
| **สลิป publish/lock แล้ว** | settlement ของเดือนนั้นแก้ไม่ได้ — เงินตรึงแล้วแต่สิทธิคิดสด ถ้าปล่อยให้ลบ สิทธิจะคืนแต่เงินไม่คืน สองฝั่งจะไม่ตรงกันถาวร |
| **ลบรายการขาดงานย้อนหลัง** | `moneyDaysFor` clamp ที่ 0 **และ**หน้ากระทบยอดขึ้นธงว่ามี settlement เกินโทษจริง — ไม่ clamp เงียบ ๆ |
| **ประเภทลาไม่จำกัดสิทธิ** (`grantedMinutes = null`) | เลือกไม่ได้ — หักจากของที่ไม่มีเพดานไม่มีความหมาย |
| **รอบคาบเกี่ยวปี** ("2026-01" = 27 ธ.ค. 2025 – 26 ม.ค. 2026) | ตัดสิทธิเข้าปีตามป้ายเดือน (2026) เก็บใน `periodYear` ตรง ๆ |
| **แอดมิน 2 คนกดพร้อมกัน** | `@@unique(employeeId, month, kind)` + upsert |
| **แก้สิทธิกลางปี จนยอดติดลบ** | ปล่อยให้ติดลบและแสดงตามจริง — ตรงกับที่ `remainingMinutes` ระบุไว้แล้วว่า "May be negative" |
| **ประเภทลาถูก archive ภายหลัง** | แถวเดิมยังนับ แต่จุดแสดงผลที่กรอง `archivedAt: null` จะไม่โชว์ — **ข้อจำกัดที่ยอมรับ** บันทึกไว้ |

## Testing

**Pure unit — `penalty-settlement.test.ts`**
- `moneyDaysFor(3, 1)` → 2
- `moneyDaysFor(1, 1)` → 0
- **`moneyDaysFor(0, 1)` → 0 ไม่ใช่ −1** ← เทสต์ที่กันบั๊กจ่ายเงินเกิน
- `moneyDaysFor(2, 0)` → 2 (ไม่มี settlement = เดิม)

**Pure unit — `balance.test.ts`**
- ยอดคงเหลือลบนาทีโทษถูกต้อง
- ประเภทไม่จำกัดสิทธิยังคืน `null` แม้มีนาทีโทษ

**Integration**
- ตัดสินจ่ายด้วยสิทธิ → **กดคำนวณเงินเดือน 3 รอบ** → สิทธิลดครั้งเดียว
  เงิน offset ครั้งเดียว ← เทสต์ที่พิสูจน์ว่าสถาปัตยกรรมนี้ทำงาน
- ลบรายการขาดงาน → `deductAttendance` ไม่ติดลบ
- เดือนที่ publish แล้ว → เขียน settlement ถูกปฏิเสธ
- เลือกประเภทที่สิทธิไม่พอ → ถูกปฏิเสธที่ server ไม่ใช่แค่ disabled ที่ UI

**Regression:** ชุดเทสต์ทั้งหมดต้องผ่าน (ฐาน 1,374 unit + 118 integration)

## Non-goals (YAGNI)

- ไม่แตะ `earlyLeaveDeduction` และโหมด flat `lateDeduction` (ไม่ใช่หน่วย "1 วัน")
- ไม่ให้พนักงานเลือกเอง — แอดมินตัดสินเท่านั้น
- ไม่ย้อนแก้เดือนที่ publish ไปแล้ว
- ไม่ทำ auto-cascade เลือกประเภทลาให้อัตโนมัติ
- ไม่หักครึ่งเงินครึ่งสิทธิในโทษก้อนเดียว
- ไม่แตะกรณีลาเป็นชั่วโมง/ครึ่งวัน — ระบบทำถูกอยู่แล้ว

## Reversibility

- schema เพิ่มตารางใหม่ + enum ใหม่ **ไม่แก้ตารางเดิม** — rollback = drop table
- **ไม่มีแถว = พฤติกรรมเดิมทุกประการ** ระบบเดิมไม่ถูกแตะ
- **การคำนวณเงินเดือนไม่เขียนอะไรเลย** — กดซ้ำได้ไม่จำกัด
- ลบแถว (soft delete) → สิทธิคืน เงินกลับมาหัก
- สลิปที่ `Published`/`Locked` ไม่ถูกแตะ (guard เดิมที่ `run.ts:316`)
- `moneyDaysFor` clamp ที่ 0 — **ไม่มีทางที่บทลงโทษจะกลายเป็นเงินเพิ่ม**
