# เลือกประเภทการลา: เอาค่าเริ่มต้นออก และโชว์สิทธิคงเหลือตอนเลือก — Design

**Date:** 2026-07-21
**Status:** Approved (design), pending implementation
**Author:** brainstormed with Claude

## Summary

ระบบ**เลือก "ลากิจ" ให้พนักงานทุกคนทุกครั้ง** โดยไม่มีใครตั้งใจ — เป็นผลข้างเคียง
ของ `orderBy: { name: 'asc' }` บวกกับ `leaveTypes[0]` และลากิจดันเป็นประเภทที่
**สิทธิน้อยที่สุดในระบบ (3 วัน/ปี)**

ผลคือปีนี้พนักงานถูกหักเงินจากการลาเกินสิทธิไปแล้ว **~฿22,600** และ **18 จาก 19
รายการเป็นลากิจ** ขณะที่ลาป่วย 30 วัน/ปี แทบไม่มีใครใช้

ไม่มี schema migration — แก้ที่การแสดงผลและค่าเริ่มต้นล้วน ๆ

## Context

### หลักฐานจาก production

```
เรียงตามตัวอักษรไทย → ตัวแรกถูกเลือกอัตโนมัติ
  1. ลากิจ      สิทธิ  3 วัน/ปี   ← ค่าเริ่มต้นของทุกคน
  2. ลาคลอด    สิทธิ 120 วัน/ปี
  3. ลาป่วย     สิทธิ 30 วัน/ปี
  4. ลาพักร้อน  สิทธิ  6 วัน/ปี

การใช้งานจริงปี 2026
  ลากิจ    ใช้ 55.3 วัน (27 คน)  ← เกินสิทธิ 18 เท่า ถูกหักเงิน
  ลาป่วย   ใช้ 13.3 วัน (10 คน)  ← เหลือเกือบทั้งหมด
```

### หลักฐานที่ชี้ว่าพนักงานไม่ได้ตั้งใจเลือก

| พนักงาน | ยื่นเป็น | เขียนในช่องเหตุผลว่า | ถูกหัก |
|---|---|---|---:|
| พรชัย | ลากิจ | **"ลาป่วย"** | ฿516.67 |
| AUNG | ลากิจ | **"ฉันไม่สบาย"** | ฿633.33 |
| JOMSANG | ลากิจ | "เจ็บตา" | (ใน ฿3,733) |
| ภัทธริดา | ลากิจ | "ท้องเสีย" | (ใน ฿1,983) |
| พิรุฬห์ลักษณ์ | **ลากิจ** | "หมอนัด" | ฿450 |
| พิรุฬห์ลักษณ์ | **ลาป่วย** | "ไปหาหมอค่ะ" | ฿450 |

**พรชัยพิมพ์คำว่า "ลาป่วย" ลงในช่องเหตุผล แต่ไม่ได้แตะ dropdown** และ
พิรุฬห์ลักษณ์ยื่นเหตุผลแทบเหมือนกันสองครั้ง แต่คนละประเภท — ครั้งหนึ่งเปลี่ยน
อีกครั้งลืม

นี่ไม่ใช่พนักงานเลือกผิด **ระบบเลือกให้แล้วเขาไม่ทันสังเกต**

### ข้อมูลที่ต้องใช้มีอยู่แล้ว

`src/app/(liff)/liff/leave/new/page.tsx` เรียก `remainingByTypeForEmployee`
อยู่แล้ว ได้ยอดคงเหลือของ**ทุกประเภท** แต่ฟอร์มใช้แค่ประเภทที่เลือกอยู่
(`leave-new-form.tsx:147`) ส่วน dropdown แสดง `annualQuota` ซึ่งเป็น
**โควตาทั้งปี — เลขเดียวกันทุกคน ไม่ว่าใช้ไปแล้วแค่ไหน**

**ไม่ต้อง query เพิ่มเลย**

## Decision

### สามอย่างที่ทำงานร่วมกัน

**1. ไม่เลือกประเภทให้อัตโนมัติ** — เริ่มที่ตัวเลือกว่าง ("กรุณาเลือกประเภท")
ทั้ง `leave-new-form.tsx:79` และ `admin-leave-form.tsx:52`

**สำคัญที่สุด และเป็นข้อที่ทำให้ 2–3 มีความหมาย** — ถ้ายังเลือกให้ คนที่รีบก็ยังกดส่ง
โดยไม่มองอยู่ดี

**2. แสดง "เหลือเท่าไร" ในตัวเลือก แทนโควตาทั้งปี**

```
ปัจจุบัน                         หลังแก้
ลากิจ — โควต้า 3 วัน       →    ลากิจ — เหลือ 0 วัน
ลาป่วย — โควต้า 30 วัน     →    ลาป่วย — เหลือ 30 วัน
ลาพักร้อน — โควต้า 6 วัน   →    ลาพักร้อน — เหลือ 2 วัน
```

ยอดคงเหลือคือเลขที่เปลี่ยนการตัดสินใจ ส่วนโควตาทั้งปีคือเลขที่ไม่ช่วยอะไร
**ให้ข้อมูลตอนที่ต้องใช้ ไม่ใช่หลังจากตัดสินใจไปแล้ว**

ประเภทที่ไม่จำกัดสิทธิ (`grantedMinutes = null`) แสดงว่า "ไม่จำกัด" ตามเดิม

**3. เตือนก่อนส่ง เมื่อประเภทที่เลือกจะโดนหักเงิน ทั้งที่ประเภทอื่นยังเหลือ**

ฟอร์มมีคำเตือน `exceedsDeduct` อยู่แล้ว แต่มันบอกแค่ว่า "จะโดนหัก" ไม่ได้บอกว่า
**"ประเภทอื่นยังเหลืออยู่"** — เพิ่มบรรทัดนั้น เพราะเป็นข้อมูลที่ทำให้คนเปลี่ยนใจได้จริง

ชั้นสุดท้ายก่อนเสียเงิน ไม่บล็อก — พนักงานอาจมีเหตุผลจริงที่ต้องใช้ประเภทนั้น

### หน้าแอดมินก็มีบั๊กเดียวกัน และแย่กว่า

`src/app/(admin)/admin/leave/new/admin-leave-form.tsx:52` ก็ `leaveTypes[0]`
เหมือนกัน **และหน้านั้นไม่แสดงยอดคงเหลือเลยสักที่** — แอดมินสร้างใบลาแทน
พนักงานโดยไม่เห็นว่าคนนั้นเหลือสิทธิเท่าไร

ต้องแก้ทั้งสองฟอร์ม และหน้าแอดมินต้องโหลดยอดคงเหลือเพิ่ม (ตอนนี้ไม่ได้โหลด)
— **หน้าแอดมินเลือกพนักงานได้ก่อน จึงต้องโหลดยอดคงเหลือหลังเลือกพนักงาน**
ไม่ใช่ตอนเปิดหน้า

## Non-goals (YAGNI)

- **ไม่เปลี่ยนลำดับการเรียงประเภทลา** — การเรียงตามตัวอักษรไม่ผิด สิ่งที่ผิดคือ
  การเลือกตัวแรกให้อัตโนมัติ แก้ที่ต้นเหตุ ไม่ใช่ย้ายปัญหาไปให้ประเภทอื่น
- **ไม่บล็อกการเลือกประเภทที่สิทธิหมด** — พนักงานอาจมีเหตุผลจริง และการบล็อก
  จะไปชนกับ `overQuotaPolicy` ที่มีกติกาของตัวเองอยู่แล้ว
- ไม่เดาประเภทจากข้อความในช่องเหตุผล — ระบบไม่ควรตีความภาษาคน
- ไม่แก้ประเภทของใบลาย้อนหลัง — เป็นการตัดสินใจของลูกค้า ไม่ใช่ของสเปกนี้
- ไม่แตะโควตาหรือ `overQuotaPolicy`
- ไม่แตะสูตรคำนวณเงินใด ๆ

## ผลกระทบที่ต้องยอมรับ

**พนักงานที่เคยกดส่งได้เลยจะต้องกดเพิ่มหนึ่งครั้ง** — เป็นความเสียดทานที่เพิ่มขึ้นจริง
ยอมรับได้เพราะราคาของการไม่มีความเสียดทานคือ ~฿22,600/ปี ที่ตกกับพนักงาน

## Reversibility

- ไม่มี schema migration ไม่มีการเขียนข้อมูล
- ย้อนกลับด้วยการ revert commit เดียว
- **ไม่กระทบใบลาที่ยื่นไปแล้ว** — เปลี่ยนเฉพาะสิ่งที่ฟอร์มแสดงและค่าเริ่มต้น
- ไม่แตะสูตรเงิน สิทธิ หรือการอนุมัติ

## Testing

**Pure/unit** — ตรรกะที่แยกออกมาได้:
- แปลงนาทีคงเหลือเป็นป้ายในตัวเลือก: 0 → "เหลือ 0 วัน" · `null` → "ไม่จำกัด" ·
  ค่าติดลบ → แสดงติดลบ (ดู I-7 ในสเปกอีกฉบับ — formatter ปัจจุบันโชว์ค่าติดลบ
  เป็น "0 ชม.")
- ตัดสินว่าควรเตือน "ประเภทอื่นยังเหลือ" ไหม: เลือกประเภทที่เหลือ 0 ขณะที่มีประเภท
  อื่นเหลือ > 0 → เตือน · ทุกประเภทเหลือ 0 → ไม่เตือน (ไม่มีทางเลือกให้แนะนำ)

**Integration**
- ส่งคำขอโดยไม่เลือกประเภท → ถูกปฏิเสธที่ server ไม่ใช่แค่ disabled ที่ปุ่ม

**Manual (เบราว์เซอร์)**
- เปิดฟอร์ม → **ไม่มีประเภทไหนถูกเลือก** และปุ่มส่งกดไม่ได้
- ตัวเลือกแสดงยอดคงเหลือของแต่ละประเภท ตรงกับหน้าสรุปวันลา
- หน้าแอดมิน: เลือกพนักงาน → ยอดคงเหลือของคนนั้นปรากฏในตัวเลือก
- ทดสอบด้วยภาษาที่ไม่ใช่ไทยอย่างน้อยหนึ่งภาษา (พม่า/ลาว/เขมร) — ป้ายต้องแปล

**Regression:** ชุดเทสต์ทั้งหมดต้องผ่าน (ฐาน 1,424 unit + 195 integration)
