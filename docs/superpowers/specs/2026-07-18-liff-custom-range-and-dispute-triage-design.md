# เลือกช่วงวันที่เองใน LIFF + คิว "ต้องตรวจสอบ" ที่คัดแยกได้ — Design

**Date:** 2026-07-18
**Status:** Approved (design), pending implementation
**Author:** brainstormed with Claude

## Summary

งานสองชิ้นที่ไม่ต้องรอการตัดสินใจจากเจ้าของระบบหรือลูกค้า:

1. **พนักงานเลือกช่วงวันที่เองในหน้ารายงาน LIFF** — ลูกค้าทำเครื่องหมาย
   *"(เพิ่มใหม่)"* ไว้ **backend รองรับครบแล้ว ขาดแค่ UI**
2. **คิว "ต้องตรวจสอบ" คัดแยกไม่ได้** — รายการแสดงแค่ชื่อ/เวลา/ระยะทาง
   ไม่บอกว่าแต่ละแถวติดธงเพราะอะไร และตัวเลข badge ไม่ตรงกับรายการที่ดูได้จริง

ไม่มี schema migration ไม่แตะสูตรเงินเดือน

## Context

### 1 — ช่วงวันที่ใน LIFF

`resolveReportPeriod` (`src/lib/reports/period.ts:37-63`) รองรับ `from`/`to`
พร้อม validation ครบแล้ว (regex, วันที่มีจริง, `from <= to`) และคืน
`month: null` เมื่อเป็นช่วงกำหนดเอง

แต่ `src/app/(liff)/liff/summary/page.tsx:40` ประกาศ `searchParams` เป็น
`{ m?: string }` และบรรทัด 45 ส่งเพียง `{ m: params.m }` → **เส้นทาง from/to
ไม่มีทางถูกเรียก** เป็นกรณี backend เตรียมไว้แล้วแต่ UI ไม่เคยต่อ

`DateRangeField` (`src/components/ui/date-range-field.tsx`) เป็น client
component ที่ใช้ `useLocale()` จาก next-intl อยู่แล้ว → **ใช้ใน LIFF ได้ทันที
ครบทั้ง 6 ภาษา** ไม่ต้องสร้างตัวเลือกวันที่ใหม่

### 2 — คิวต้องตรวจสอบ

หลังจากเพิ่มธงเซลฟี่ (ขึ้น prod แล้ว `965c12b`) คิวนี้มีสองสาเหตุปนกัน:
GPS ผิดพลาด กับ รูปเซลฟี่ไม่ได้มาจากกล้องสด ซึ่ง**ต้องการการตรวจคนละแบบ**
(GPS → ดูแผนที่, เซลฟี่ → ดูรูป)

แต่รายการแสดงเพียง `name` / `nickname` / `clockInLabel` / `distanceMeters`
(`disputed-client.tsx`) — เหตุผลอยู่ในแผงรายละเอียดที่ต้องกดเข้าไปทีละแถว
(`disputed-client.tsx:163`)

**ผลที่แย่กว่านั้น:** แถวที่ติดธงเซลฟี่มี GPS ปกติ จึงแสดง `distanceMeters`
ที่ดูปกติดี — แอดมินเห็นแล้วงงว่าทำไมแถวนี้ถึงอยู่ในคิว

**บั๊กที่ยืนยันแล้วในหน้าเดียวกัน:** badge นับด้วย `count()` แบบไม่จำกัด
(`_load-badge-counts.ts:31`) แต่รายการดึงมา `take: 50` (`_load-inbox.ts:47`)
และไม่มีปุ่มโหลดเพิ่ม → เกิน 50 เมื่อไหร่ ตัวเลขจะไม่ตรงและแอดมินกดดู
ส่วนที่เหลือไม่ได้ (ปัจจุบันมี 0 รายการบน prod จึงยังไม่ระเบิด)

## Decision

### 1 — เลือกช่วงเอง โดยใช้ของที่มีอยู่

- ขยาย `searchParams` ของหน้า LIFF summary ให้รับ `from`/`to` แล้วส่งต่อ
  ทั้งสามค่าเข้า `resolveReportPeriod` — **ไม่แตะตรรกะ validation เดิม**
- เพิ่ม client component สลับโหมด: รายเดือน (ลูกศรเดิม) ↔ ช่วงกำหนดเอง
- โหมดช่วงกำหนดเองใช้ `DateRangeField` ที่มีอยู่ ส่งค่าด้วย GET form →
  `?from=YYYY-MM-DD&to=YYYY-MM-DD`
- เมื่ออยู่โหมดช่วงเอง ต้องมีทางกลับไปโหมดรายเดือนที่เห็นชัด

### 2 — ทำให้คัดแยกได้ และเลิกซ่อนการตัดรายการ

- **แสดงเหตุผลในรายการ** ไม่ใช่แค่ในแผงรายละเอียด
- **แสดงระยะทางเฉพาะเมื่อเกี่ยวข้อง** — แถวที่ติดธงเซลฟี่ (GPS ปกติ)
  ไม่ควรโชว์ตัวเลขระยะทางที่ดูปกติจนชวนสับสน
- **เลิกตัดรายการแบบเงียบ** — loader คืนจำนวนทั้งหมดมาด้วย ถ้าถูกตัด
  ให้บอกตรง ๆ ว่า "แสดง 50 จาก N รายการ"

**จงใจไม่ทำ pagination เต็มรูปแบบ** — ปัจจุบันมี 0 รายการ การทำ pagination
ให้คิวที่ว่างเปล่าคือการเดาอนาคต การทำให้การตัดรายการ*มองเห็นได้*แก้ปัญหา
"ตัวเลขไม่ตรงกัน" ได้จริงด้วยต้นทุนที่ต่ำกว่ามาก และถ้าวันหนึ่งตัวเลขนั้น
โผล่ขึ้นมาจริง เราจะรู้ทันทีว่าถึงเวลาทำ pagination แล้ว

## Non-goals (YAGNI)

- ไม่เพิ่มการแจ้งเตือนวันเกิดทาง LINE — โควตา LINE เต็ม 300/300 อยู่ การเพิ่ม
  ข้อความตอนนี้สวนทางกับแนวทางลดข้อความที่ยังรอการตัดสินใจ และอาจต้องรื้อทิ้ง
- ไม่ทำ pagination เต็มรูปแบบให้คิวต้องตรวจสอบ
- ไม่แตะ `resolveReportPeriod` หรือ validation ของมัน
- ไม่แก้ schema / migration
- ไม่ทำตัวกรองแยกประเภทในคิว (แสดงเหตุผลให้เห็นก็พอสำหรับปริมาณปัจจุบัน)

## Architecture

### ส่วน 1 — ช่วงวันที่ใน LIFF

**`src/app/(liff)/liff/summary/page.tsx`**

```ts
  searchParams: Promise<{ m?: string; from?: string; to?: string }>;
```
```ts
  const period = resolveReportPeriod(
    { m: params.m, from: params.from, to: params.to },
    todayYmd,
  );
```

`resolveReportPeriod` ตรวจ `from`/`to` เองอยู่แล้ว — ค่าที่ผิดรูปแบบจะตกกลับไป
โหมดรายเดือนโดยอัตโนมัติ **ห้ามเพิ่ม validation ซ้ำที่หน้าเพจ** (จะกลายเป็น
ตรรกะสองที่ที่เพี้ยนจากกันได้)

**`src/app/(liff)/liff/summary/period-picker.tsx`** *(สร้างใหม่, client)*

- รับ `month: string | null`, `from: string`, `to: string`, `todayYmd`
- `month != null` → โหมดรายเดือน: ลูกศร ← เดือน → (ลิงก์ `?m=`) +
  ปุ่ม "เลือกช่วงเอง"
- `month == null` → โหมดช่วงเอง: `DateRangeField` + ปุ่มค้นหา +
  ลิงก์ "กลับไปรายเดือน" (`?m=<เดือนของ from>`)
- ส่งค่าด้วย GET form ไปยัง path เดิม — ได้ URL ที่แชร์/บุ๊กมาร์กได้ และ
  ทำงานได้แม้ JS ยังไม่โหลด
- `max={todayYmd}` — ไม่ให้เลือกอนาคต

i18n keys ใหม่ใต้ `summary` ใน `messages/th.json` + `en.json`:
`customRange` = "เลือกช่วงเอง", `backToMonthly` = "กลับไปรายเดือน",
`applyRange` = "ดูช่วงนี้", `rangeLabel` = "ช่วงที่เลือก"

### ส่วน 2 — คิวต้องตรวจสอบ

**`src/app/(admin)/admin/attendance/disputed/_load-inbox.ts`**

เปลี่ยนให้คืนทั้งแถวและจำนวนรวม:

```ts
export type DisputedInbox = { rows: DisputedRow[]; total: number };
```

ใช้ `prisma.$transaction([findMany({ take: 50 }), count()])` โดย **where
เดียวกันทั้งสองคำสั่ง** — ประกาศ where เป็นตัวแปรเดียวแล้วใช้ซ้ำ ห้ามเขียนสอง
ที่ (นี่คือรากของบั๊ก badge-vs-list ตั้งแต่แรก)

**`disputed-client.tsx`**

- เพิ่ม `reason: string` เข้าไปในข้อมูลของแต่ละแถว (มีอยู่ใน VM แล้ว
  แค่ยังไม่ถูกส่งมาที่รายการ) แสดงเป็นบรรทัดรองใต้ชื่อ
- **`distanceMeters` แสดงเฉพาะเมื่อมีค่า** — แถวที่ติดธงเซลฟี่ GPS ปกติ
  การโชว์ระยะทางที่ดูปกติทำให้เข้าใจผิดว่าไม่มีปัญหา
- ถ้า `total > rows.length` แสดงบรรทัดท้ายรายการ:
  *"แสดง {rows.length} จาก {total} รายการ — กรองช่วงวันให้แคบลงเพื่อดูที่เหลือ"*

**`page.tsx`** — ส่ง `total` ต่อลงไป และคง `disputedCount` ของแท็บให้ใช้
`total` (ไม่ใช่ `rows.length`) เพื่อให้ตรงกับ badge ใน sidebar

## Testing

**Unit**
- `resolveReportPeriod` — มีเทสต์อยู่แล้ว ไม่แตะ; เพิ่มเทสต์ที่ยืนยันว่า
  หน้า LIFF ส่ง `from`/`to` ต่อจริง (ทดสอบที่ระดับ resolve ไม่ใช่ render)
- `loadDisputedCheckIns` — `total` สะท้อนจำนวนจริงแม้ `rows` ถูกตัดที่ 50,
  และ where ของทั้งสองคำสั่งตรงกัน (สร้างข้อมูลจำลอง 51 แถว)
- `period-picker` — ตรรกะสร้าง URL (pure function แยกออกมาทดสอบได้)

**Regression:** ชุดเทสต์ทั้งหมดต้องผ่าน (ฐานปัจจุบัน 1301 unit + 118 integration)

**Manual smoke**
- LIFF summary: กด "เลือกช่วงเอง" → เลือกช่วง → ตัวเลขเปลี่ยนตามช่วง →
  กลับไปรายเดือนได้
- URL ที่มี `?from=&to=` เปิดตรงได้และแสดงช่วงนั้น
- `?from=` ที่ผิดรูปแบบ → ตกกลับโหมดรายเดือน ไม่พัง
- คิวต้องตรวจสอบ: เห็นเหตุผลของแต่ละแถวโดยไม่ต้องกดเข้า

## Reversibility

- ไม่มี schema change / migration
- ส่วน 1 เป็นการ *อ่าน* พารามิเตอร์เพิ่ม + UI ล้วน ไม่เขียนข้อมูลใด ๆ
- ส่วน 2 เป็นการอ่าน + แสดงผล ไม่เขียนข้อมูลใด ๆ
- ไม่มีคำสั่งเขียน/ลบ/อัปเดตใหม่ในทั้งสองส่วน
- ย้อนกลับได้ด้วยการ revert commit เดียว; URL เก่าที่ใช้ `?m=` ยังทำงานเหมือนเดิม
