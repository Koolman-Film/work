# สเปกการออกแบบเอกสาร (Word / PDF) — Koolman

**สำหรับ:** เอกสารที่ส่งออกนอกระบบ — สรุปงานถึงลูกค้า รายงาน ข้อเสนอ
**อ้างอิงจาก:** ระบบดีไซน์ **Sapphire Editorial** ใน `src/app/globals.css`

เอกสารที่ส่งให้ลูกค้าต้องดูเป็นของบริษัทเดียวกับแอป — สเปกนี้แปลง design token
ของแอปเป็นค่าที่ใช้ในเอกสาร Word ได้ตรง ๆ **อ่านไฟล์นี้ก่อนสร้างเอกสารทุกครั้ง**

## 2. ตัวอักษร

แอปใช้ `--font-sans: IBM Plex Sans Thai → Sarabun → …`

**ในเอกสารใช้ `Sarabun`** — เป็น fallback ลำดับถัดไปที่ประกาศไว้ในระบบดีไซน์เอง
จึงไม่หลุดจากภาษาการออกแบบ และติดตั้งอยู่บนเครื่องที่ใช้ render (IBM Plex Sans Thai
มักไม่มีในเครื่องทั่วไป — ถ้าอ้างชื่อไปแล้วไม่มี Word จะสลับฟอนต์เอง ซึ่งคุมไม่ได้)

## 3. หน้ากระดาษ

- **A4** (11906 × 16838 DXA) — มาตรฐานไทย ไม่ใช่ Letter
- ขอบ: บน/ล่าง 1080 DXA (0.75″) · ซ้าย/ขวา 1080 DXA
- **ไม่ใส่หัวกระดาษในหน้าปก** ใส่ตั้งแต่หน้า 2
- ท้ายกระดาษ: เลขหน้าชิดขวา 9pt สี `64748B`

## 4. องค์ประกอบ

### เส้นคั่นใต้หัวเรื่อง 1
ขอบล่างของย่อหน้า หนา 12 (1.5pt) สี `3955E8` — **ไม่ใช้ตารางทำเส้น**

### ตาราง
- ความกว้างคอลัมน์ต้องกำหนดทั้ง `columnWidths` ของตาราง **และ** `width` ของทุกเซลล์
  หน่วย `DXA` เสมอ (`PERCENTAGE` พังใน Google Docs) และผลรวมต้องเท่ากับความกว้างตาราง
- หัวตาราง: พื้น `3955E8` ตัวอักษรขาว
- แถวสลับ: พื้น `F0F5FF` (แถวคู่) — เว้นไว้ถ้าตารางสั้นกว่า 4 แถว
- เส้น: `E2E8F0` หนา 4 (0.5pt)
- ระบายสีใช้ `ShadingType.CLEAR` เท่านั้น (`SOLID` จะออกมาดำ)
- ตัวเลขเงินชิดขวาเสมอ

### กล่องเน้น (callout)
ตาราง 1×1 พื้นตามบทบาท ขอบซ้ายหนา 24 (3pt) สีเข้มของบทบาทนั้น
- ต้องตัดสินใจ → พื้น `FEF3C7` ขอบ `B45309`
- ทำเสร็จแล้ว → พื้น `D1FAE5` ขอบ `047857`
- ความเสี่ยง/เงินที่เสีย → พื้น `FEE2E2` ขอบ `B91C1C`
- ข้อมูลทั่วไป → พื้น `F6F8FB` ขอบ `3955E8`

### รายการ
ใช้ `numbering` + `LevelFormat.BULLET` — **ห้ามพิมพ์ `•` ลงไปตรง ๆ**

### ภาพหน้าจอ
- กว้างไม่เกิน 6.5″ จัดกึ่งกลาง
- มีคำบรรยายใต้ภาพเสมอ 9pt สี `64748B`
- ครอบเฉพาะส่วนที่พูดถึง ไม่ใส่ทั้งหน้าจอ
- `ImageRun` ต้องระบุ `type:` ("png" / "jpg")

## 5. หลักการเขียนสำหรับเอกสารถึงลูกค้า

- **ภาษาธุรกิจ ไม่ใช่ภาษาเทคนิค** — ไม่มีชื่อไฟล์ ชื่อฟังก์ชัน หรือ commit
- **เรื่องที่ต้องตัดสินใจต้องเด่นที่สุด** และแยกออกมาเป็นส่วนของตัวเอง ไม่ปนกับสิ่งที่ทำเสร็จ
- **ทุกตัวเลขต้องตรวจสอบได้** — ถ้าไม่ได้ยืนยันจากข้อมูลจริง อย่าใส่
- **บอกข้อจำกัดตรง ๆ** สิ่งที่ระบบยังทำไม่ได้ต้องมีหัวข้อของตัวเอง ไม่ซ่อนท้ายเอกสาร
- ปี พ.ศ. สำหรับลูกค้า (2569) ไม่ใช่ ค.ศ.
- เงินใส่คั่นหลักพันและทศนิยม 2 ตำแหน่งเสมอ (฿1,166.67)

## 6. ขั้นตอนสร้างและตรวจ

```bash
node scripts/<ชื่อ>.js                                    # เขียนด้วย docx (npm)
soffice --headless --convert-to pdf out.docx              # แปลงเป็น PDF
pdftoppm -jpeg -r 100 out.pdf page                        # แปลงเป็นภาพ
# แล้วเปิดดูทุกหน้า — ห้ามส่งโดยไม่ดู
```

**ต้องเปิดดูผลจริงทุกครั้ง** โดยเฉพาะเอกสารภาษาไทย — สระลอย ฟอนต์สลับ และ
ตารางล้นขอบจะเห็นก็ต่อเมื่อ render ออกมาเป็นภาพเท่านั้น
